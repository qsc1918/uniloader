### 4.1 命名空间：`Mappings not present!` 就是「26.x 不再混淆」的直接证据

日志里 **`Mappings not present!`**，并且**反混淆/重映射相关的日志条数为 0**
（`grep -ciE "deobfuscate|Runtime mod remapping|Remapping"` → `0`）。
与 `docs/stage0/T0.2-version-matrix.md` 第 2 节的代码分析完全一致：

- 没有 mappings 文件 → `MappingConfiguration.computeRuntimeNamespace()` 返回 `official`；
- `getDefaultModDistributionNamespace()` 也保持 `official`；
- `MinecraftGameProvider.initialize()` 的 `!gameNs.equals(runtimeNs)` 不成立 → **不做反混淆**；
- `RuntimeModRemapper` 因 `modNs.equals(runtimeNs)` 直接返回 → **不做 mod 重映射**。

即：**26.3 上内核与模组天然同处 `official` 命名空间，零重映射**，D1 想解决的「统一命名空间」自动成立。

### 4.2 客户端专属 mod 被正确跳过

（同一矩阵在更早一次运行中打印的清单，当时 `run/mods` 里有 sodium/iris/modmenu）

```
SERVER environment disabled: [fabric-model-loading-api-v1, fabric-renderer-api-v1, sodium, iris, modmenu,
  fabric-key-mapping-api-v1, fabric-sound-api-v1, fabric-screen-api-v1, fabric-rendering-v1, fabric-renderer-indigo]
```

sodium / iris / modmenu 与 fabric-api 的客户端专属子模块被按 `environment` 正确过滤，
既没有报错也没有硬塞进去——这是 `ModResolver` 的环境判定在起作用。

### 4.3 依赖求解器给出的是可读结论，不是崩溃

第一次用 10 个 mod 跑（当时矩阵里没有 `forge-config-api-port`）时的输出：

SAT4j 求解、原因归类（`HARD_DEP_NO_CANDIDATE`）、修复建议、中文本地化**全部生效**。

### 4.4 真实 mixin 冲突被显式报出（不静默）

`architectury` 与 `carpet` 同时改写了 `getClimateSettings`，加载器**明确警告并说明谁覆盖了谁**：

```
Method overwrite conflict for getClimateSettings in architectury.mixins.json:BiomeAccessor
  from mod architectury, previously written by carpet.mixins.Biome_scarpetMixin. Skipping method.
```

这是阶段 7 的 T7.4（Hook 冲突检测）与 T10.x 的**真实样本**：
上游 Fabric 的做法是「后到者跳过 + WARN」，而 UL 的工程纪律要求**确定性顺序 + 冲突检测告警**，
这条日志正好是「现状 vs 目标」的起点。**已存档为验收素材。**

## 5. 实测过程中修掉的 4 个问题（都在脚本/环境层，内核本身没改）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | `UnsupportedClassVersionError: net/minecraft/bundler/Main ... class file version 69.0` | 用 Java 21 跑 MC 26.3（需要 25）。报错发生在 loader 内部，极易被误判成「内核坏了」 | `run/env.sh` 改为**按 major ≥ 25 挑 Java**，找不到就明确报警（`UL_JAVA` 可覆盖） |
| 2 | `Failed to load eula.txt` → 服务端拒绝启动 | `eula.txt` / `server.properties` 是相对路径，必须让**工作目录 = 游戏目录**；`-Dfabric.gameDir` 只影响 loader 自己的判断 | `run/{server,client}.sh` 在 exec 前 `cd "$GAME_DIR"` |
| 3 | `ClassNotFoundException: ...KnotServer` | classpath 里只有内核 jar，缺 installer 依赖（asm/mixin），且内核 jar 路径是相对的，`cd` 之后失效 | 新增 `run/loader-classpath.sh` 统一拼装（内核 + 依赖 + 原版游戏），全用绝对路径 |
| 4 | mod 矩阵 2 个 slug 404、1 个缺依赖 | slug 写错；依赖没进矩阵 | 修正 `matrix.yml`（`rei`、`travelersbackpack`），把依赖也列为矩阵条目 |

另外把 `fetch-mods.sh` 的网络访问从 Python `urllib` 换成 `curl`：
Windows 上 Python 的 ssl 不认系统证书库，走本地代理时会 `CERTIFICATE_VERIFY_FAILED`，
而 curl 用系统（schannel）证书库没这个问题。
