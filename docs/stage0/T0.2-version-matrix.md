## 2. ★ 阻塞项：MC 26.3 目前**没有** intermediary 映射

这是本次核实发现的、会影响阶段 1 开工的事实，必须写下来：

```
$ curl -sSI https://maven.fabricmc.net/net/fabricmc/intermediary/26.3/intermediary-26.3-v2.jar
HTTP/1.1 404 Not Found

$ curl -sS https://maven.fabricmc.net/net/fabricmc/intermediary/maven-metadata.xml | tail -5
      <version>25w45a</version>
      <version>25w46a</version>
      <version>1.21.11-pre5</version>
      <version>1.21.11-rc3</version>
      <version>1.21.11</version>
    </versions>
    <lastUpdated>20251209160445</lastUpdated>
```

- 目录里**没有任何 26.x 条目**（`net/fabricmc/intermediary/` 列表按字典序排到 `25w46a` 之后直接跳到 `3D Shareware v1.34`）。
- 最新可用的是 **1.21.11**（`maven-metadata.xml` 的 `lastUpdated` 为 2025-12-09）。
- 另一方面 `fabric-api` 仓库自己写的是 `minecraft_version=26.3`，说明 Fabric 生态在往 26.3 走，但**intermediary 的发布没跟上**（或者换了发布渠道，本次核实范围内没找到）。

### 影响

D1 的做法是「内核跑在 mojmap 下，Fabric mod 从 intermediary 重映射过去」。
**没有 intermediary，就没有源命名空间，这条重映射链就缺了起点。**

### 三条出路（阶段 1 的 T1.1 开工前必须选定）

| 方案 | 内容 | 代价 | 备注 |
|---|---|---|---|
| **A. 换首个目标版本为 1.21.11** | 拿完整的 official→intermediary→named 映射 | NeoForge/Forge 侧的 846/623 个 patch 是 26.3 的，对不上 1.21.11 的字节码；需要另找 1.21.11 分支 | 最稳，但把「四家同版本」这件事推后 |
| **B. 内核直接用 mojmap，Fabric mod 也以 mojmap 为目标** | 不再需要 intermediary：mod 侧的 refmap 目标命名空间改成 named | 需要 Fabric 生态在 26.3 上发布 **named 目标**的产物（loom 的 `refmapTargetNamespace=named`）；对存量 mod 无效 | 对**新建**的 mod 生态最干净，对存量 mod 无解 |
| **C. UL 自行维护 26.3 的 intermediary** | 自己生成 official→intermediary 映射 | 维护成本极高，且与 Fabric 官方映射可能分叉 | 不建议，除非确认官方确实停了 |

**当前阶段 0 的处理**：D1 实验用 **1.21.11 的真实映射**验证机制本身（映射合并、tiny-remapper 配置、门闸、性能），
结论与 MC 版本无关；26.3 的映射来源问题作为阶段 1 的前置阻塞项留在本文档，不假装已解决。

## 3. 构建侧的两处实测结论（已修复在 fork 里）

| 现象 | 根因 | 处理 |
|---|---|---|
| `./gradlew build` 在 `:proguardJar` 失败：`can't find superclass or interface java.lang.Object` | 上游把 Java 8 工具链的 rt.jar 硬编码为 `jre/lib/rt.jar`；当解析到的是 **JRE**（而非 JDK）时，路径是 `lib/rt.jar`，ProGuard 于是拿到一个不存在的 libraryjar | fork 内改为两种布局都探测（`loader/build.gradle`，注释标注为 `UniLoader fork patch (T0.1)`） |
| 用 Gradle 9.7.1 构建时 `:minecraft` 报 `Could not get unknown property 'sourceSets' for project ':' of type DefaultProjectDependency` | `minecraft/build.gradle` 里 `implementation project(":").sourceSets.main.output` 在 9.7 上 `project(":")` 返回 ProjectDependency | **不改上游代码**：按上游指定的 9.1.0 构建（wrapper 已锁定），并在本文档记录，避免后人误升 Gradle |

## 4. 网络与代理（本机环境相关，不进代码）

本机在受限网络下，构建与实验的下载需要代理。用环境变量传入即可，**不要写进仓库文件**：

```bash
export https_proxy=http://127.0.0.1:7897
export http_proxy=http://127.0.0.1:7897
export GRADLE_OPTS="-Dhttps.proxyHost=127.0.0.1 -Dhttps.proxyPort=7897 -Dhttp.proxyHost=127.0.0.1 -Dhttp.proxyPort=7897"
```

Gradle 分发包（9.1.0）在国内镜像上可用：`https://mirrors.cloud.tencent.com/gradle/gradle-9.1.0-bin.zip`
（`services.gradle.org` 会 307 跳到 GitHub Release，在受限网络下不稳定）。
